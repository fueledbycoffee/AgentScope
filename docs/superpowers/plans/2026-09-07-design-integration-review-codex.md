# Cross-review: issue #30, before implementation

References below use `P` = `docs/superpowers/plans/2026-09-07-design-integration.md`, `D` = `research/design/claude/3-console/README.md`, and `M` = `research/design/claude/3-console/mockup.html`. Line numbers refer to the reviewed files. Baseline: `pnpm --dir web test` passes all 29 tests (2 files).

1. **P1 — Chips can claim filters the server never applies.** `P:44-50` defers model/period but ships day/tool/quality URL chips. Neither sessions nor summary accepts those parameters (`docs/api/v0.1.md:106,135`; `web/src/api/types.ts:5`). A pasted URL can therefore display a narrowed scope over broader numbers even without chart wiring. Keep unsupported chips gallery-only, and explicitly reject or disclose unsupported URL parameters. Specify canonical keys, duplicate handling and Clear/removal semantics; model selection must update the select, not create a competing chip (`D:31`; `M:792-803`).

2. **P1 — The promised receipt and provenance have no data contract.** `P:49,69-72` requires scoped import counts, filename, mapping revision and import-report links. Summary has no import count; raw records expose only hash, locator, payload, text and derived marker; session detail supplies no import identity (`web/src/api/types.ts:71-106`; `docs/api/v0.1.md:114-145`). Counting the paginated, unscoped imports ledger cannot produce an agent-scoped receipt, and a hash alone does not identify the correct import/mapping. Declare backend prerequisites or explicit unavailable/deferred fields before implementation; do not fabricate provenance or totals.

3. **P1 — URL storage does not define navigation preservation.** `P:37-50` omits search-preserving redirects, rail links, row links, breadcrumbs, pagination and Back/Forward behavior. Existing links drop search (`web/src/App.tsx:10-19`; `web/src/pages/Dashboard.tsx:47`; `web/src/pages/Imports.tsx:72`). Require `/dashboard?source=…` to retain scope through redirect, Overview → Sessions → detail, reload and Back, with offset reset on scope edits and history restored on navigation. Detail must retain list context without filtering the entity (`D:17,25,143`). Define whether returning from FileBar routes restores scope. These are acceptance cases for the #12 path (`P:103-104`; `docs/adr/ADR-006-ui-design-direction.md:52-53`).

4. **P1 — “Every query key includes it” names an architecture that is absent.** `P:46-47` assumes query keys, but the app uses callback identity and effect cleanup, with no query library (`web/src/useResource.ts:5-17`; `web/package.json:15-19`). A fresh scope object on every render, passed into the existing callback dependencies, can repeatedly reload and hide results. Specify stable primitive dependencies or an explicitly budgeted query migration; include scope plus pagination only on scoped endpoints, entity IDs on detail, and hash/locator on raw records. Preserve immediate stale-data suppression and late-response rejection for KPIs, receipt and table together (`web/src/App.test.tsx:243-256`), including rapid edits and history traversal.

5. **P2 — Selects have no option source or synchronization contract.** `P:44-50,63` does not say how Source/Agent selects obtain complete options. Today's controls accept arbitrary text, including `trace & lab` (`web/src/pages/Dashboard.tsx:17-26`; `web/src/App.test.tsx:249-254`); the API provides no facets endpoint (`docs/api/v0.1.md:104-145`). Deriving options from one filtered session page hides valid values. Choose an honest temporary input/combobox or a complete option source, preserve unknown URL values, and make controls controlled by the URL so Back and chip removal update their displayed selection. State whether edits apply immediately or on submit.

6. **P2 — The temporary screen differs from Console beyond the stated chart deferral.** `P:37-42,87-91` preserves today's Sessions/Model calls/Tool calls/Input tokens tiles and 50-row overview (`web/src/pages/Dashboard.tsx:13-14,45-55`), while Console specifies Sessions/Model calls/Input/Output and eight preview rows (`D:110`; `M:721-725`). Output metrics, universal units/coverage, cache totals and comparability are absent from `web/src/api/types.ts:102-106`, so the promised definition surfaces also cannot match `D:47,119`. List these as temporary deviations with owners (#10/#11), including the shortened Definitions table. ADR-006 makes these rules binding (`docs/adr/ADR-006-ui-design-direction.md:26-36`); general “re-hosting” is not a sufficient exception.

7. **P2 — Keeping behavior and changing only test labels is contradictory.** `P:87-91` leaves real policy conflicts unresolved: the current test requires sessions to remain usable when metrics fail (`web/src/App.test.tsx:207-215`), whereas Console replaces the overview body on error (`D:111`); history tests require zero entity counts for failed/duplicate rows (`web/src/App.test.tsx:275-285`), whereas Console requires dashes (`D:108`). The new tile arrangement and immediate selects also exceed label updates. Decide each behavior explicitly, revise only the corresponding assertions, and retain safeguards for preview invalidation, duplicate submission, queued batches and late import completion (`web/src/App.test.tsx:99-202`).

8. **P2 — Applying theme before React render does not prevent first-paint flash.** `P:24-26` waits for `main.tsx`, a module loaded at the end of the body (`web/index.html:10-12`); CSS can paint the system palette before a saved opposite preference executes. Specify a synchronous, guarded bootstrap in the document head before first paint, shared preference validation, and fallback when storage throws. A “small toggle” must expose all three choices and current selection; system must follow OS changes without overwriting the stored preference. Test saved light on dark OS, saved dark on light OS, system changes and invalid/unavailable storage.

9. **P2 — Root-only theme selectors cannot render both gallery themes side by side.** `P:15-17,95-97` scopes overrides to `:root[data-theme]`; a dark gallery subtree will inherit the document theme. Use isolated documents or deliberate subtree token overrides, including light overrides inside a system-dark document. Portal popovers/dialogs must retain the specimen's theme. Test actual resolved colors rather than assuming a `data-theme` attribute changed them.

10. **P2 — Fontsource family names do not match the verbatim tokens.** `P:11,21-23` combines `--sans: "Geist"` / `--mono: "Geist Mono"` (`M:25-26`) with packages whose documented families are `Geist Variable` and `Geist Mono Variable`; standard imports would download fonts while rendering fallbacks. Alias custom faces or explicitly change the tokens. Choose WOFF2 subsets/axes and `font-display`, and compare emitted bytes for variable faces against the limited weights in `D:60`; self-hosting alone is not a size budget. Verify loaded faces and absence of external font requests. Sources: [Geist installation](https://fontsource.org/fonts/geist/install), [Geist Mono installation](https://fontsource.org/fonts/geist-mono/install).

11. **P2 — Focusability is not keyboard drill accessibility.** `P:79-83` does not specify per-datum role/name, Enter/Space activation, visible focus or exact-value hint updates; a hidden table containing only values provides no equivalent action. The reference implements all of those (`D:126`; `M:784-805,813`). Recharts documents chart-level arrow navigation, not this complete drill contract ([maintainer accessibility documentation](https://github.com/recharts/recharts/wiki/Recharts-and-accessibility)). Select a version and prototype the actual shapes/events early; implement accessible controls in the fallback with visible-on-focus access. Verify both chart orientations and activation in a browser. Recharts is not yet installed (`web/package.json:15-19`).

12. **P2 — jsdom assertions cannot prove native modal focus trapping.** `P:68-69,101-102` promises focus-trap tests, but current dialog methods are per-file mocks that merely toggle `open` (`web/src/App.test.tsx:40-46`); shared setup has none (`web/src/test-setup.ts:1-6`). New component tests calling `showModal()` will need shared mocks, and those mocks cannot validate browser modality or native Escape. Keep unit coverage for close/cancel state, unmount, opener restoration and verbatim inert text (`web/src/App.test.tsx:329-352`); add a real-browser Tab/Shift-Tab/Escape/backdrop check before calling the primitive accessible, even if #12's full smoke remains deferred. Test StrictMode setup/cleanup and prevent clicks inside drawer padding from being mistaken for backdrop clicks.

13. **P2 — Lazy loading alone does not exclude the gallery from production.** `P:95-96` gates route registration but leaves the dynamic-import declaration unspecified. An unconditional `lazy(() => import(...))` or shared barrel can retain gallery chunks/assets, and chart imports through shared modules can ship Recharts even while charts are gallery-only. Put the entire import path behind the compile-time DEV branch; keep fixtures and gallery CSS out of production import chains. Add a production-build assertion for emitted JS/CSS/assets and ensure `/gallery` is unavailable in preview. `web/package.json:9` provides a build, but `P:93-104` never checks its output.

14. **P2 — The contrast test needs a usage matrix and cascade model.** `P:98-100` cannot infer “every surface it is used on” by parsing tokens alone. Include status-on-soft, chip labels, inverse primary-button text, hover/focus and chart states; resolve light, explicit dark and system-media rules independently rather than taking the last token declaration. Actual light `--ink-4` on `--surface-3` is **4.43:1**, so a blanket cross-product contradicts verbatim tokens (`M:13-18`); `--s4` on white is **3.65:1**, contradicting the README's claimed 4.1–6 range (`D:77`) while passing the proposed graphics threshold. Define supported pairings, fail on missing cases, and verify representative computed styles; literal hex tests cannot catch a broken theme selector or inherited legacy color.

15. **P2 — Generic state blocks do not specify route states or layout migration.** `P:54,87-102` omits receipt loading/failure, no matches versus an empty later page, session 404 with a scoped return link, no compatible mapping, batch FileBar identity, and per-expander mapping failures. Import disclosure receipts and collapsed raw/emissions samples are missing from the inventory despite `D:42,97,103`; assign these explicitly to #30 or #8/#9 (`research/design/DECISION.md:34-36,49-54`). Preserve current batches (`web/src/pages/Import.tsx:23-38,57-70`). Explicitly retire old global `header`, table, control and hard-coded color rules (`web/src/index.css:11-49`) and verify sticky offsets, 36 px density and internal scrolling at 900 px (`D:62,131`; `M:315-320`); token substitution alone cannot deliver the shell.

16. **P2 — The 12-hour estimate omits major work and validation.** `P:108-115` budgets charts plus the entire gallery at 2 hours and all page migrations, test changes and contrast at another 2; the design itself allows a day for Recharts care (`D:91`). New Sessions/Mappings/Definitions routes, scope/history tests, API gaps, theme bootstrap, browser modal checks and production/font audits have no explicit allowance. Break these out, identify backend dependencies, and provide a range after the chart/scope prototypes; budget roughly 3–5 UI days as a provisional review estimate, excluding backend work, or reduce #30's commitments. Acceptance must include typecheck, lint, all existing tests and production build (`web/package.json:7-13`), not only Vitest.
