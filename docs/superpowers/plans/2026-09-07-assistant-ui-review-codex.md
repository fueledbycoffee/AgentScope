This is an offline source review; no packages were installed, no network requests were made, and no implementation tests were run. Package release dates, peer dependencies and library runtime signatures in the plan are unverified. The #13 routes and fake adapter exist; the #14 compatible adapter is not merged here. The React chatbot library requirement is accepted. The icons-over-labels amendment in `research/design/DECISION.md` governs over ADR-006's original icon restriction. Saving an executable revision explicitly before preview is compatible with the current API, provided the following gaps are fixed.

1. **P1 — The automatic send flow does not specify an enforceable consent and freshness boundary.** Plan lines 65–68 describe prepare → show digest changed → run, while lines 93–95 require opening the drawer for that digest. After reviewing sample-bearing digest A, typing a reply produces B; automatically running B violates the latter rule. Opening a loading drawer must not acknowledge a response that arrives after it closes. The listed invalidators also omit identity, upload, kind and history. A successful backend digest check cannot prevent an old, internally consistent request from being sent after the user changes the page: `RunAssistant.execute` only compares the submitted request with its re-preparation (`backend/src/agentscope_app/application/use_cases/assistant.py:280`).

   **Fix:** Specify the transitions in planned `web/src/assist/assistRuntime.ts` before implementation. Snapshot the complete request, assign a monotonically increasing context generation, and retain the exact request alongside its prepared response. Reject late prepare/run results on generation or upload mismatch. Every run must use that snapshot plus its returned digest; invalidate synchronously on any context mutation. For sample-bearing contexts, preparation must pause for acknowledgement of the successfully rendered `payload_text` for the current digest. A new digest, including one obtained after `409 stale_context`, requires a fresh review before sending. Allow only one active run; either lock editing while it runs or retain a late proposal separately without overwriting intervening edits. Abort on navigation where possible, but use generation checks even when cancellation cannot stop backend work. Display `payload_text` verbatim through `PayloadDrawer.tsx`/`JsonText`, never a re-serialization of `payload`.

2. **P1 — The field-table model is incomplete and can silently change executable mappings.** Plan lines 51–60 list a single source path, but DSL v1 has mutually exclusive `path`, ordered fallback `paths`, and presence-sensitive `literal`; it also has `bounds`, `type`, `empty_as_missing` and `default`. Rule IDs are editable identity/reference data, not just incidental row labels. The bundled TraceLab mapping already requires wildcard timestamp bounds. Stringifying literals or defaulting every omitted property changes semantics; for example an omitted `native_key` can infer `external_id`, whereas `native_key: []` is explicit. Unknown keys generate warnings and remain in saved source documents, so rebuilding only recognized properties is lossy. Non-executable assistant drafts can contain malformed rules and fields that a rows-only model cannot represent.

   **Fix:** Make the original JSON document the canonical editor state and use `mappingRows.ts` as an indexed view with narrowly scoped edits, preserving untouched values, unknown keys, property presence and array order. Define controls for all field options, rule add/delete/rename and parent-reference handling, ordered transforms including both shorthand and object forms, `enum_map.mapping` and its `unmapped` policy, typed condition values, and document `unmapped: [{path, reason}]` and notes. Preserve malformed sections in an accessible JSON repair view rather than dropping them. Use `profile.selector`/`relative` when suggesting paths: `$.tools[*].tool_name` becomes `select: "$.tools[*]"` with field `$.tool_name`; root fields inside that rule use `@root`. Ordinary fields, fallback paths and conditions reject wildcards; timestamp `bounds: min|max` requires one wildcard-containing path. Respect the 16-segment/18-digit-index grammar. References: `backend/src/agentscope_app/domain/mapping/mapping-dsl-v1.schema.json`, `domain/mapping/parser.py:277`, `:409`, `domain/mapping/paths.py`, `backend/mappings/tracelab-v1.json:37`. Expand round-trip and edit tests beyond the bundled/fake documents to exercise every variant and invalid intermediate state.

3. **P1 — “Document → rows → document is identity” ignores loss at the JSON transport boundary.** `web/src/api/index.ts` uses `response.json()` and `JSON.stringify`, and `web/src/api/types.ts` represents every JSON number as a JavaScript `number`. A condition value of `9007199254740993` is rounded before the table sees it. Even `{"literal": 1.0}` is re-emitted as `{"literal": 1}`, which the backend deliberately preserves as different Python number types and can stringify differently for a string target. A round-trip test starting from an already parsed JavaScript object will miss both losses. The existing regression cases in `backend/tests/interfaces/test_api_assistant.py` explicitly protect numeric conditions and float literals.

   **Fix:** Include a lossless mapping codec at the API/editor boundary in `web/src/api/index.ts`, `api/types.ts` and `assist/mappingRows.ts`, retaining numeric lexemes and emitting them as JSON numbers, not strings. Keep the representation through prepare, run, validate and save serialization; choose and validate the codec as an explicit dependency/design task. Test raw response text → unchanged editor → outgoing request → backend read/execution for large integers, fractional values and `1.0`, plus typed null/false/zero/empty-string literals. If full preservation is deferred, explicitly detect and block affected edits/saves with a documented limitation; do not claim lossless DSL support.

4. **P1 — Save is the only stated execution gate; a fresh preview of the exact revision is missing.** Plan lines 84–89 put both Preview and Import behind Save, allowing import without preview and leaving the saved ID valid after an edit, ambiguity selection, undo or replacement proposal. A late validation/save/preview response can also mark a newer document ready. `POST /api/imports` does not require proof of preview, so the UI owns this requirement. `proposal.executable` only means contract-valid, not suitable for the source (`docs/api/v0.1.md:121`).

   **Fix:** Add document version, validation version, saved-document snapshot/ID and preview binding to `Assist.tsx`/`ActionBar.tsx`. Save requires a current server validation with `executable: true` and an explicit user action; warnings remain visible but do not necessarily block. Preview requires that the displayed document equals the saved snapshot. Import requires a successful, displayed preview for that same upload, saved ID and sample setting, and a separate explicit confirmation naming file/hash, source and revision. Invalidate downstream gates immediately on edits/undo/proposal application; ignore late completions and guard duplicate submissions. Display normalized emissions, sampled count, partial/rejected/ignored counts and warnings, including the fact that the full import can differ. Reuse the safeguards and confirmation content in `web/src/pages/Import.tsx`; neither the chat runtime nor any model-suggested action may invoke save/import. Test `200 executable:false`, refusal and failed runs without losing the existing document. Clarify that Save-before-Preview is an API constraint, not an intrinsic DSL requirement.

5. **P1 — Ambiguity options are prose, not executable edit instructions.** The plan promises that every option chip applies an edit (lines 61–62), but the actual contract is `{target, options: string[], what_settles_it}`. `_ambiguities` merely converts arbitrary model values to strings (`backend/src/agentscope_app/application/use_cases/assistant.py:565`). The fake includes `"a validated swe-chat tag"` as an option, not a valid literal to blindly insert. Targets such as `model_call.started_at` identify an entity/field, not a unique rule when several rules emit that entity. Explanations' `path` is a source-evidence path, not a patch address.

   **Fix:** In `MappingTable.tsx`/`assistRuntime.ts`, treat options as suggestions. Auto-edit only explicitly supported, locally validated operations where the user has an unambiguous selected rule/field; for example setting `timestamp_format` to an allowed enum on a timestamp field. Show the exact proposed change and `what_settles_it`. For prose or multiple candidate rules, open the field editor or insert the suggestion into a pending revision message that goes through prepare/consent. Never interpret model text as arbitrary JSON paths/code. Revalidate and invalidate execution gates on accepted edits. Add unknown-option, invalid-option, stale-suggestion and duplicate-entity-rule tests.

6. **P2 — “Issues appear on their rows” does not cover the parser's paths or asynchronous validation.** Actual issue paths include `$`, `dsl_version`, `rules[0].id`, `rules[0].fields`, `rules[0].fields.started_at.bounds`, transform/condition indices and `unmapped[0].reason` (`domain/mapping/parser.py:97`, `:201`, `:409`). Missing required fields have no existing field row. JSON Schema validators typically produce a different location format; structural and semantic validation are not interchangeable. Reordering a rule while validation is pending can attach a diagnostic to the wrong row.

   **Fix:** Specify a path-to-control resolver in `assist/mappingRows.ts` that translates the chosen client's schema locations and the backend's document-index paths, uses stable UI row identities independent of editable rule IDs, and applies only diagnostics for the validated document version. Provide document/rule/unmapped-level issue summaries with links to controls or the JSON repair view when no row exists. Keep stage/code/severity, label fields with rule and target, and connect errors through `aria-invalid` and `aria-describedby`. Tests must include missing fields, root errors, duplicate IDs, unknown keys, nested transforms, reordering and out-of-order validation responses. Server `executable` remains authoritative.

7. **P2 — The library message list cannot be sent directly as API history.** Plan lines 27–29 equate the thread with history, but the API only accepts plain `{role: user|assistant, content: string}` turns, at most 20 with 4,000 characters each; `revise` also needs a mapping and a separate message (`docs/api/v0.1.md:99`, `interfaces/api/schemas.py:56`). Library message IDs, parts and status are separate concerns. A growing thread eventually fails with 400 before the server can trim its context. Initial chat submission with no proposal cannot use `kind: revise`. The TraceLab fake returns no questions or ambiguities, so constructing assistant text only from those fields yields an empty response bubble.

   **Fix:** Define typed profile/prepare/run/save DTOs and API helpers in `web/src/api/types.ts` and `index.ts`, plus explicit UI-message ↔ plain-history conversion in `assistRuntime.ts`. Preserve the visible thread while sending a bounded history projection and visibly reporting omitted history. Send the new user text once as `message`, with prior completed turns in history; exclude transport/system notices. Define initial `propose`, subsequent `revise`, empty-success receipt, pending/retry/cancel behavior and retention of the user's draft after errors. Handle 400 field details, 404 upload, 409 stale context and 413 context-too-large, as well as 502/503. Retry must not create duplicate turns or silently rerun generation. Derive metadata from actual `proposal.model`/`diagnostics`; the current response has no dedicated “adapter notes” field.

8. **P2 — The entry routes do not have a complete bootstrap contract.** The import report's `ImportedFile` has SHA, filename and mapping but no `upload_id` (`web/src/api/types.ts:20`; `docs/api/v0.1.md:175`). There is no GET upload metadata endpoint in `routers.py`. The plan therefore cannot directly construct its report → `/import/assist/:uploadId` link. It also never specifies where required mapping `identity.name/source` come from, how a refresh restores file identity, or how leaving the current Import page preserves its local batch. A corrected mapping cannot repair an already committed report by simply re-importing: duplicate detection uses file bytes plus source, regardless of mapping revision (`application/use_cases/imports.py:353`).

   **Fix:** Specify a reload-safe bootstrap and entry-point contract in `web/src/App.tsx`, `pages/Import.tsx`, `pages/Imports.tsx` and planned `Assist.tsx`. Obtain and validate user-owned name/source before prepare; keep them consistent with the current document. Use `useFileBar` for the file/hash/format/record count and revision. For report entry, explicitly add an upload-resolution API contract or route the user through re-upload of the original file and verify its SHA; include selecting the correct file and loading its existing mapping. Define a clear missing/expired-context recovery and preservation of the pending import batch. Explain that a saved correction is reusable but does not replace observations from an already committed file; do not silently change source to bypass deduplication. Add refresh, Back, multi-file report and already-imported tests.

9. **P2 — The library choice is plausible, but the compatibility and fallback decision is not reviewable yet.** Neither the chatbot packages nor a JSON Schema validator are present in `web/package.json`/`web/pnpm-lock.yaml`. The plan's React-19 “yes” column does not establish compatibility with this repository's React 19.2, Vite 8, TypeScript 6 or strict compiler settings. It supplies no reproducible package metadata or minimal external-store adapter. “CSS-variable theming” also does not identify whether the selected primitives ship styling, require optional styles, or need a different framework's generated components. Publish recency alone does not demonstrate an integration advantage. These are unverified claims in this offline review, not findings that a particular package is incompatible.

   **Fix:** Keep `@assistant-ui/react` as the conditional first choice and move a bounded integration spike ahead of page construction. For the exact selected version, record peer/engine/license/export evidence, typecheck a minimal external-store adapter using the real message and callback types, and production-build with the existing Vite/TS configuration. Prove pending consent, one-shot completion, disabled send, cancellation and disabled unsupported retry/edit/branch/attachment actions. Style the actual primitive classes directly with existing Console tokens in `assist/chat-theme.css`; test light, explicit dark and system dark without adding a parallel theme system. Record bundle/dependency cost. Compare alternatives on required local-state ownership, network/runtime dependencies, theming work and accessibility behavior rather than assumed cloud requirements or age. A `@chatscope/chat-ui-kit-react` fallback is acceptable under the owner's library requirement if it passes the same spike and tests; make failure criteria and a decision deadline explicit. Do not install both or silently switch late in implementation. Package verification belongs to implementation when dependencies are available; this review does not authorize network access.

10. **P2 — The two backend routes need ordering and validation semantics specified.** `GET /api/mappings/{mapping_id}` is already registered at `interfaces/api/routers.py:100`; appending `GET /api/mappings/schema` beneath it would resolve `schema` as a mapping ID and return 404. The static schema declares draft 2020-12, so a client validator must support that dialect and its `if`/`then`/`oneOf` constructs. It supplies structural validation only and deliberately allows properties that the parser diagnoses as warnings. The validate route's status behavior and malformed-body contract are currently unspecified.

   **Fix:** Register the static GET before the dynamic GET, load the existing packaged schema without a second divergent copy, and choose a 2020-12 client validator configured without coercion, default insertion, removal of unknown properties or remote schema fetching. Define `POST /mappings/validate` as 200 `{issues, executable}` for an accepted document, including non-executable drafts, with full `{stage,path,code,message,severity}` issues and `parsed.is_executable`; malformed envelopes use the existing 400 error format. State whether non-object documents reach the parser or fail body validation. Keep this operation free of persistence and assistant calls. Add route tests for literal `schema` resolution, real/unknown mapping IDs, valid/invalid/warning-only documents, malformed bodies, schema equality and unchanged mapping/import counts. Update `docs/api/v0.1.md` and the frontend DTOs together.

11. **P2 — Icon names and library accessibility claims do not cover this interaction.** “Examples on hover” excludes touch and keyboard users. Reusing `DataTable` does not label embedded inputs, and adopting a thread primitive does not verify announcements, composer keyboard behavior or focus restoration.

   **Fix:** In `EvidenceRail.tsx`/`ProfileTable.tsx`, print exact coverage as field records / inspected records, nulls / observed values, and inspection/truncation limits; make examples available through a keyboard/touch disclosure and name every type glyph. In `Conversation.tsx`, define a labeled thread/log and composer, polite announcements for new replies and pending state without re-announcing the entire thread, Enter/Shift+Enter and IME behavior, visible focus, scroll-to-latest behavior and focus retention after replies/undo. Expose sample/collapse toggle state. Use the existing `IconButton` pattern for repeated actions, while retaining text for first-use save/import confirmations as the design amendment allows. Do not put disabled-action explanations solely in unfocusable disabled buttons' tooltips. Define responsive inspector collapse and a usable table scroll region. Add browser keyboard-only checks through table → composer → payload dialog → acknowledgement, including modal focus return, narrow viewport/zoom and both themes. Extend `web/src/styles/tokens.test.ts` for actual text/surface and focus/control pairings, not just nominal library variables.

12. **P1 — The proposed Playwright acceptance flow can pass without testing revision or execution of the new mapping.** For TraceLab, `FakeMappingAssistant._envelope` calls `_tracelab(head)` without passing the message/current mapping (`backend/src/agentscope_app/infrastructure/llm/fake.py:79`); `_tracelab` returns the bundled mapping, which already maps `user`. Asking “map the user too” does not revise it. Separately, `web/e2e/smoke.spec.ts:45` imports those bytes into `tracelab`, while `web/playwright.config.ts:5` shares one database across specs. Running the assistant flow afterward against that source yields a duplicate; unchanged totals prove nothing about the new document. Running it first can instead invalidate the smoke test's expected first commit. The epoch draft is contract-valid with either timestamp format, so “validate clean” does not prove that selecting seconds changed execution.

   **Fix:** Give the assistant browser flow an isolated backend/database or a unique source with source-filtered totals, independent of spec ordering. Assert the report is `committed`, its file uses the saved mapping ID, and expected observations were inserted. Retain a separate duplicate test. Use the fake's supported epoch message revision to assert an actual document change and a preview emission with the expected ISO timestamp; use TraceLab to test explanations, bounds and baseline counts. Alternatively extend the fake with a documented deterministic TraceLab revision and corresponding backend tests. Set `AGENTSCOPE_LLM_PROVIDER=fake` explicitly after inherited environment in `web/e2e/start-backend.mjs`, and assert `fake/deterministic-1` in the response. This works before #14 merges and must remain independent of live credentials/providers.

13. **P2 — The test list lacks negative assertions for the invariants being claimed.** A mocked prepare → run happy path and “run disabled until prepared” do not prove that no run slips through a stale completion, that samples are withheld pending review, or that a late save cannot unlock import. Backend assistant tests already exercise failure envelopes, but those do not exercise browser state. The plan's E2E never turns sample inclusion on and does not verify the no-write boundary.

   **Fix:** Add a named regression matrix to plan §5 and implement it in `assistRuntime`/component/API tests: inverted prepare/validate/run completion order; every context invalidator; sample toggle on/off and changed-digest re-review; drawer closed before prepare resolves; double submit; navigation and upload changes in flight; 400/404/409/413/502/503; null refusal and non-executable repaired draft; edit during save/preview; undo restoring content but invalidating stale gates; history limits; malformed/non-unique ambiguity targets; and all DSL forms from findings 2–3. Assert exact request bodies and absence of `/assistant/run` until eligible. In Playwright, assert no mapping save or canonical import request during analysis, chat and table edits, and inspect server mapping/import state before explicit actions (the profile cache is the permitted assistant-side write). Assert Import remains disabled until the exact saved revision has a current preview. Keep the existing smoke suite, and require frontend typecheck/lint/unit tests/production build, browser tests and relevant backend route/parser tests as completion gates.

14. **P3 — Transient proposal metadata cannot be presented as saved-revision audit data without an association policy.** Plan lines 90–92 put model/digest next to a saved revision in `MappingsPage` “from the page state.” That page fetches only server mapping summaries and the assistant page unmounts on navigation (`web/src/pages/Mappings.tsx`). Metadata would disappear on refresh and may describe a proposal preceding manual edits. An idempotent save can return an existing revision, including its original `created_by`; `routers.py:88` stamps the actor for new saves, not necessarily the returned record.

   **Fix:** Keep a clearly labeled “assistance used this session” receipt beside the saved result in `Assist.tsx`, bound to the actual save response and identifying subsequent manual edits. If cross-page display is retained, define an in-memory store keyed by saved ID with explicit session-only provenance and missing-data behavior; never imply server-persisted audit history. Do not fabricate `created_by` in the client or add model/digest to executable DSL data. Persisted audit support would be a separately specified API change.

15. **P2 — The 1.1-day estimate omits most integration risk and has the dependency order reversed.** Plan lines 140–143 allocate 0.3 day to both a lossless DSL editor model and a concurrent, consent-aware chat state machine, then leave the new library integration until last. The older shell plan's roughly one-day implementation is not evidence for this more stateful feature.

This is an engineering estimate, not a measured duration. If 1.1 days is fixed, split the deliverable and state which acceptance criteria move to a follow-up; do not retain the full-completion claim. Correct the opening claim that #14 already exists in this checkout, and keep live two-model evidence outside this fake-based UI gate as already scoped.
