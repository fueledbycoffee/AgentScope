# Review of issue #16 implementation plan

Reviewed `2026-09-07-second-source-two-models.md` against ADR-005, the configuration evidence log, API v0.1, both scripts, the LLM adapters, the SWE-shaped test helpers, and `web/e2e/`. This is an offline plan review: no provider calls or local SWE-chat data were available. The requested `2026-09-07-assistant-ui.md` is absent from this checkout; PR #40's UI routes and prepare/run, validate/save flow are treated as given by the contract, not as missing implementation findings.

1. **P1 — Duplicate detection invalidates both the second configuration's import and the proposed replay.** Plan lines 39–55 reuse the same files and source without defining database isolation. The API skips bytes already committed for a source regardless of the newly selected mapping (`docs/api/v0.1.md:174–217`). Config B can therefore reach an import report without executing its mapping; restarting the backend and uploading again produces a duplicate with no emitted entities, not the promised identical committed counts. The existing browser smoke explicitly tests this duplicate behavior.

   **Fix:** Give A and B separate temporary databases/raw stores with identical input bytes and the same source namespace. For each, save both UI-created mappings and take a consistent snapshot after saving but before importing. Import the pair, then replay from a separate copy of that pre-import snapshot with the provider disabled. Preserve the saved mapping IDs/revisions and verify document hashes across the restart. Alternatively, restore the exact exported documents into a clean database and record the new ID bindings, with a separate persistence check. Assert `status=committed`, zero duplicate records, and actual expected emissions on both original and replay runs. Test same-database duplicate import separately as idempotency evidence. Do not alter source names or source bytes merely to evade duplicate detection.

2. **P1 — Selecting `fake` does not prove provider-disabled replay or absence of assistant calls.** Plan lines 51–57 leave a fully working assistant installed. `FakeMappingAssistant.complete()` can produce executable SWE-chat drafts, and a browser request log cannot detect an internal assistant call made by an import service. A regression that silently regenerates mappings could pass this procedure.

   **Fix:** Run replay with an unavailable adapter, for example an explicitly unsupported provider value that the current container routes to `UnavailableMappingAssistant`, with the API key empty and outbound provider transport denied. In the API regression test inject a recording assistant whose `complete()` raises immediately, and assert its call count remains zero even if a caller catches the exception. A separate control may verify that an explicit assistant run is unavailable; exclude that control from the replay call counter. Check no browser assistant requests as additional evidence. CI must use synthetic inputs and denied/mocked transports, with real credentials excluded from configuration loading; `web/e2e/start-backend.mjs` currently inherits the environment and starts in the backend directory, so reuse requires explicit isolation from `backend/.env`.

3. **P1 — “Completing the workflow” lacks a semantic acceptance gate.** Plan lines 29–33 correctly permit human corrections, but lines 16–19 repeat the historical claim that an editable TraceLab draft completed the workflow. `llm_smoke.py` performs only upload/profile/prepare/run: it never saves, previews, or imports, and returns exit code 2 for a non-executable draft. Those older runs are useful adapter evidence, not evidence for the issue #16 definition. An executable document also proves only contract validity, not correct interpretation of SWE-chat (`docs/api/v0.1.md:121–128`). A successful import with only session emissions or many rejected call rows could otherwise satisfy the plan's arrows.

   **Fix:** Define a per-configuration acceptance matrix covering both tables: live proposal returned; every revision and human correction attributed; final executable documents explicitly saved through the UI; previews reviewed; fresh imports committed; agreed source coverage and canonical results checked; offline replay passed. Separate model outcome (executable/draft/refusal/error), human-assisted workflow outcome, and source coverage (supported/partial/blocked). Manual corrections can count as human-assisted completion, but replacing most or all of a draft must be described as such, not as model-generated success. Refusals, transport errors, old TraceLab smoke results, and fake runs cannot fill either live SWE-chat completion slot. Qualify the historical wording in both evidence logs when publishing the new report. Set required coverage before evaluating the models; missing required entities must leave the gate incomplete rather than be excused by “unmapped.”

4. **P1 — The SWE-chat row interpretation needs a concrete audit before using the drafts or bundling a mapping.** Plan lines 74–76 treat DSL limitations as fields to omit. Some affect what an observation means. `fake.py:128–250` maps sessions to session contributions, assumes `role=assistant` means model calls, and maps `role=tool_use` to tools. The synthetic helper supplies exactly those roles and even supplies `agent` on conversation rows; it is not confirmation of the real source. `docs/datasets/README.md` explicitly leaves assistant-entry/API-call equivalence unvalidated and identifies `turn_type` and `is_continuation` as source fields. DSL v1 has no cross-record/table joins or aggregation; a tool `parent` refers to an earlier root model-call rule on the same record, not a prior conversation row.

   **Fix:** Add a local, aggregate-only source audit: role/turn-type/continuation distributions, native-ID behavior, per-session candidate call counts versus declared `api_call_count`, tool-use/result pairs, missing values, and timestamp wrappers. Define explicit inclusion/exclusion predicates from that evidence. Sessions and conversations need separate mappings, bound to their respective files, using the same `session_id`/source so the reducer merges metadata. Do not turn session token totals or declared call counts into synthetic model calls. Keep unknown token semantics explicit and avoid double counting continuation or result rows. Standalone tool-use observations may have a null model-call link; separate result rows cannot provide joined status, end time, or latency through v1. Record those omissions and expected warnings/coverage, and preserve missing measures as null. Use `.iso` accessors for Arrow timestamp wrappers where the profile confirms them. If essential call classification requires unsupported joins/grouping, label support partial and leave the required acceptance gate open. Do not change the DSL on freeze day to conceal that limitation.

5. **P2 — The report does not retain a complete, attributable proposal-to-import chain.** Plan lines 58–67 specify summary fields and “the two saved mapping documents,” although two configurations times two tables can produce four distinct final documents plus revisions. A corrections diff without its starting proposal is not reviewable; a digest of an unavailable context cannot reconstruct it. A model ID, executable flag, and final mapping alone do not show what the live model actually contributed. Optional `llm_smoke.py --save-recording` captures only the last provider response of a separate smoke run, not the UI run or its whole repair/revision sequence.

   **Fix:** Define stable run IDs and an artifact index for every configuration/file/context-mode run. Retain reviewed, sanitised proposal envelopes from each UI outcome, validation issues, revision messages, manual diffs with explicit base/target hashes, and every final saved document. Link each saved ID/revision/content hash to its preview, import report, and replay. Deduplicate identical documents by hash while retaining all run bindings. Record configured and endpoint-reported model IDs, model vendor, timestamps, failure/status, generation attempts, adapter notes, and whether executable output arrived initially or after repair when observable. Label unavailable internal details honestly. If transport recordings are added, follow `backend/tests/llm_recordings/README.md`: captured bodies plus provenance sidecars, synthetic bodies clearly labelled, and neither presented as a substitute for live UI/import evidence. The report can omit prepared payload text while retaining enough safe inputs and version information to regenerate and verify its digest locally.

6. **P2 — Reproduction inputs and comparison assertions are underspecified.** Plan lines 37–38 record only a manifest digest; the script defaults to `data/samples/swe-chat/`, whereas this plan uses `swe-chat-1/`. Selection depends on upstream bytes, seed, per-agent cap, reader behavior, and Arrow output. The report omits the exact build/launch commands, full endpoint root/port, max tokens, context versions, and restart boundaries. JSON-mode fallback is remembered by the adapter for the process lifetime, so a preflight can affect later UI calls if it shares that process. Also, import `entities.session` counts emitted observations, not distinct sessions; a conversation mapping can emit a session contribution for every row.

   **Fix:** Include the pinned dataset revision and upstream hashes, safe manifest metadata, seed/cap, exact sampling command with explicit output directory, output hashes/bytes/row counts, and locked tool versions. Treat 12/518 as an expected historical excerpt to verify, not guaranteed local contents. Document exact web build/script/backend commands and working directories, isolated storage lifecycle, full non-secret endpoint root, adapter/model configuration, timeout/max tokens, context/prompt/profiler/sanitizer versions, and fresh-process boundaries. Specify which profile-only/sample-enabled proposal advances to revision/save and prepare every revision anew. For comparisons, account for every file's accepted/partial/rejected/ignored/duplicate records, warnings and rejects, then separately compare source-scoped distinct sessions, model/tool observations, timestamps, token coverage/semantics, representative relationships, and Parquet `row:N` provenance. Compare normalized semantic outputs excluding generated IDs/times, not only totals. Live model output need not reproduce byte-for-byte; saved-mapping execution must.

7. **P1 — “No payload text” is insufficient protection for committed evidence and fixtures.** Plan lines 47–67 allow verbatim revision messages, mapping diffs, saved documents, and request logs without an export policy. These can contain source literals, paths, identifiers, credentials, or model-echoed text even if the prepared payload is omitted. `llm_smoke.py` scrubs the configured API key, not all sensitive source content. The normal Playwright configuration retains failure traces containing DOM/network material. The dataset notes explicitly say no SWE-chat data is committed pending sensitivity/terms review; `.gitignore` ignores Parquet outside `fixtures/` and is not an export review mechanism.

   **Fix:** Use an explicit reviewed export allowlist: aggregate report metadata, sanitised proposals/diffs, schema-only mapping documents, provenance, and independently authored synthetic fixture generators/expected outputs. Keep actual SWE-chat Parquet, raw rows, prepared samples, local databases, `.env`, auth headers, unreviewed response bodies, HARs/traces/videos/screenshots, and full request dumps local and excluded from staging. Record browser request method/path/status or counters without bodies/headers; disable sensitive trace capture for the live harness or route it to a local excluded directory. Scan and manually inspect all candidate artifacts, including mapping notes, literals, messages and nested JSON/escaped strings; identify any sanitised artifact as transformed, with its own hash. Do not copy real rows and merely call them synthetic. Any future dataset redistribution needs its own terms, sensitivity and attribution review. Reviewed executable mappings alone may become bundled product mappings; evidence drafts must remain non-loadable artifacts.

8. **P2 — The replay fixture test can become circular and does not specify which mappings it protects.** Plan lines 55–57 say synthetic SWE-shaped fixtures and saved documents will be committed, without requiring the actual final documents from both configurations or independent expected results. Existing fake tests largely exercise shapes that match the fake's assumptions. Rebuilding mappings from the fake, modifying them to fit easier test data, or asserting only that replay counts equal an incorrect first import would leave semantic regressions undetected.

   **Fix:** Parameterize API replay over every distinct final document pair identified by the live report, using exact content hashes. Generate tiny synthetic Parquet tables in temporary storage with explicit Arrow types, including shared sessions across files, a session without calls, assistant/continuation cases, tool-use and tool-result rows, missing optional values, and at least one expected diagnostic. Author expected entity/record outcomes independently of the mapping. Verify persistence across container restart, real execution into empty import state, selected field values/relationships/provenance, and zero assistant calls. Keep raw Parquet generation offline rather than force-adding ignored binaries under `backend/tests/`. Synthetic replay proves deterministic execution of saved documents; it does not certify real dataset semantics or a deployed model.

9. **P1 — Free-model failure has no terminal outcome, and the fallback can violate model distinctness.** Plan lines 25–26 and 88–89 acknowledge availability but do not say what happens if A fails, B exhausts candidates, or only one vendor answers. The existing log already contains rate limits, retired models, overload and truncation. A local endpoint running the same model weights is not a second model, and two configuration labels or two OpenRouter slugs from one vendor do not meet the stated ADR alternative.

   **Fix:** Permit bounded substitutions for either slot, recording exact selected IDs and vendors and checking that two distinct models qualify; two OpenRouter selections must be from different vendors. Use a genuinely different local model only if available and actually run through the same UI procedure. Set a finite attempt/time budget consistent with the adapter's one repair and bounded transport retries; log every failed candidate and rerun the complete accepted procedure for any replacement. Keep smoke preflights profile-only unless visible sample review is explicitly implemented: the current smoke script prints digest/counts and immediately calls the provider. Never silently use a paid slug, a fake, a previous TraceLab result, or a summary of an unavailable run. If two qualifying completions cannot be recorded, publish partial evidence with a pending release gate and carry the remaining verification forward.

10. **P1 — Freeze/tagging and board completion are unconditional.** Plan lines 82–84 say to tag main and mark day-3 items Done regardless of evidence, replay results, semantic omissions, or concurrent integration. A green branch test or pre-merge live run does not establish that the tagged main includes PR #40 and the exact reviewed mappings/harness. An end-of-day feature freeze can occur while verification is incomplete; an issue/release readiness claim cannot.

    **Fix:** Make the sequence explicit: integrate PR #40 and issue #16 changes; record the tested application commit and report/artifact hashes; pass the required backend, web and browser checks plus offline replay; close every required evidence/coverage gate; merge the report and fixtures; verify the final main tree corresponds to the tested product tree. Rerun affected verification if integration changes relevant behavior. Then create `v0.1.0-rc1` at that explicit commit and record the target; if the tag already exists, inspect it and never move/overwrite it silently. Mark only completed board items Done and carry blockers to #17 with links. If time expires first, declare feature freeze with verification pending and defer the acceptance tag/completion claim. Document-only report changes can reference the tested code commit without claiming a new live run.
