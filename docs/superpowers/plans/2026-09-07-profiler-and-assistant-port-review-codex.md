Evidence: inspected all 4,770 TraceLab fixture records. The SWE-chat script is `scripts/sample_swe_chat.py`, not `backend/scripts/sample_swe_chat.py`; no generated excerpt exists under this checkout's `data/samples`. Running its `build_excerpt(..., per_agent=1)` in the existing backend environment failed at line 153: Arrow cannot convert a nanosecond timestamp to Python datetime without losing precision and requests pandas. For additional evidence, I used the script's deterministic selection function to select 12 whole sessions, filtered the original Arrow tables without Python datetime conversion, and passed in-memory Parquet outputs through the production reader: 12 session rows and 518 conversation rows, all decoded successfully. This is a diagnostic substitute, not a successful run of the excerpt script. No provider calls were made.

1. **P1 — The acknowledgement does not bind the context that will actually be sent.** Plan lines 62–71 and 101–106 describe an upload-level outgoing report, but revision requests add a mapping, message and history that `GET /uploads/{id}/outgoing` cannot receive. Proposal requests also add source and name. A hash of the upload report cannot establish that those later contexts were displayed. Moreover, the documented request bodies omit both `include_sample` and `payload_sha256`, and the outgoing response omits the hash. The two-method port has no preparation operation through which an adapter can expose the claimed exact outgoing payload. Hashing `dumps_exact(context)` also does not guarantee equality with a later chat-completions request containing adapter-generated messages. This leaves ADR-005 lines 61–65 unenforced across the #13/#14/#15 boundary.

   **Fix:** define preparation and send as separate operations for a specific propose/revise request. Preparation must accept all context inputs, sanitize and bound them, freeze the outgoing content, and return its text, byte count and digest. Send must reference that prepared snapshot and explicitly acknowledge sample inclusion; reject an absent, stale or mismatched acknowledgement before invoking the assistant. Bind upload content, sample selection, mapping/message/history and relevant policy/prompt versions. Define whether the preview represents the exact model-visible context or the exact credential-free request body, and make the adapter consume the same prepared representation. A server can establish acknowledgement of displayed content, not prove a human read it. Add both request/response schemas and error examples to `docs/api/v0.1.md` and `interfaces/api/schemas.py`. Test profile-only defaults, sample requests without acknowledgement, another upload's digest, changed revision inputs, and byte-for-byte equality using a recording adapter.

2. **P1 — Redaction can occur after destructive truncation, and does not cover the whole port input.** Plan lines 23–24 first truncate examples to 80 characters; lines 36–44 then apply redaction to profile examples, including a rule for text longer than 200 characters. Under that ordering a 500-character trace becomes an apparently safe 80-character example, bypassing the long-text rule. Token recognition can likewise be broken by clipping. Filtering only examples and sample values leaves `current_mapping`, user messages and client-supplied history outside the stated sanitized-context boundary. Mapping notes or replayed conversation content can contain the same sensitive trace strings. Merely putting records under a `data` key does not establish how history roles and instructions are handled.

   **Fix:** specify full-value classification/redaction before example selection and truncation, recursively including container examples. Build a single sanitizer for the complete outgoing context; treat mapping documentation and history as untrusted data, and prevent client history from creating system/developer instructions. Define how sensitive field names that cannot be safely exposed are reported or withheld without silently rewriting executable paths. Keep redaction counts tied to actual outgoing content. In `domain/redaction.py`, the application context builder and their tests, cover long text, credentials crossing the 80-character boundary, nested examples, secrets in mapping notes/history, and instruction-like trace content. The same sanitized snapshot must serve preview and send.

3. **P1 — Refusing to start without the compatible adapter breaks the existing offline application.** Plan lines 94–97 make container startup fail when `openai_compatible` is selected before #14 lands. That is already the default in `backend/src/agentscope_app/infrastructure/settings.py:14`, and the existing API fixture constructs settings without overriding it (`backend/tests/interfaces/test_api_e2e.py:20`). Consequently #13 would disable upload, saved mapping replay and dashboards for the default configuration, contrary to ADR-005 lines 68–72 and the day-3 gate. Changing CI to fake would hide the product regression.

   **Fix:** wire an unavailable-assistant implementation, or defer assistant configuration failure until an assistant operation is invoked, while constructing all existing services normally in `interfaces/api/container.py`. Return a documented application error for unavailable assistance without silently substituting a fake in production. Test application startup and saved mapping preview/import with the adapter absent or provider disabled; use a spy that fails on any assistant invocation during replay. Keep separate explicit-fake CI tests for the assisted flow.

4. **P2 — “Long base64/hex runs” conflicts with ordinary identifiers in both datasets.** Plan lines 40–43 leave thresholds, boundaries and precedence unspecified, while lines 120–121 promise no false positives. The TraceLab fixture contains the ordinary tool ID `call_cbHrgTXCdPO0xkmbtFSSrbb0`: all 3,926 Codex entries in `tools[*].tool_call_id` contain a 24-character base64-alphabet run. A 16-hex-run detector also matches 2,492 `round_id` values and 1,797 tool IDs. The diagnostic SWE selection contains a 30-character session identifier with a base64-alphabet run repeated in 66 conversation rows and their turn IDs. These are collision measurements for illustrative patterns, not results from an implemented redactor. The current plan provides no rule that resolves them while preserving its promised identity evidence.

   **Fix:** replace the vague rule with reviewed patterns, token boundaries and precedence. Known credential formats must remain redacted even when stored under an ID-like key; do not blanket-allowlist keys. Preserve demonstrated native-ID formats where justified, and use an explicitly documented policy for ambiguous opaque strings, such as stable placeholders retaining equality. Add negative cases derived from both sources, including UUIDs, prefixed call/round IDs, model names and timestamps, alongside positive credential cases in the proposed redaction tests. Reuse the fixture's existing `scripts/scan_tracelab.py` checks as evidence, not as proof of anonymization.

5. **P2 — Record/path/depth limits do not bound traversal, examples or provider payload size.** Plan lines 30–32 and 53–55 permit an arbitrarily wide array at a single path. A valid JSONL record containing a large numeric array can stay below the reader's 4 MiB line limit and consume just two profile paths; neither the long-text rule nor the 20-record sample limit reduces it. Container examples can retain that entire array even when recursive profiling stops at depth 8. Long keys, distinct-value storage and client-supplied history introduce additional unbounded work or output. The reader's file limits are not an appropriate model-context budget.

   **Fix:** give `domain/profile.py` explicit limits for visited nodes/array items, distinct-state memory, key/example size and container examples; give the application context builder a final serialized-byte budget covering sample, profile, mapping and history. Bound sample selection to the same inspected window and make selection deterministic. Report each truncation/omission, including exhausted output budget; never hash a preview and then trim it differently for sending. Add large-array, wide-object, deep-container, long-key and oversized-history tests, with assertions on traversal and outgoing bytes rather than only the number of paths.

6. **P2 — Profile paths are not necessarily representable or directly usable as DSL field paths.** Plan lines 16–18 promise verbatim copying and lines 117–119 promise every random-JSON path is valid. `domain/mapping/paths.py:14` only accepts identifier keys matching `[A-Za-z_][A-Za-z0-9_-]*`; JSON objects and accepted Parquet schemas can contain keys such as `a.b`, `a b`, `0` or Unicode names. Flattening `{"a.b": 1}` to `$.a.b` silently points at a different value. Separately, `$.turns[*].role` is a valid path expression but an invalid ordinary field path: `domain/mapping/parser.py:399` rejects wildcards there, except the supported timestamp-bounds case.

   **Fix:** reuse `parse_path` and report unaddressable keys separately with a reason and an unambiguous source locator. Do not invent quoted-key syntax or expand DSL v1 implicitly. Represent array evidence with the selector and item-relative field path, for example `select: $.turns[*]` plus `path: $.role`; distinguish root-scoped access and timestamp bounds. Test punctuation, Unicode, literal-dot/nested-key collisions and nested arrays. Validate generated mapping fragments through `parse_mapping`, not just `parse_path`.

7. **P2 — Null rates and type statistics lack a consistent observation unit.** Plan lines 20–28 define `present` in root records but do not define whether `null`, type histograms and distinct ratios count records or array elements. For one record with two null `tools[*].x` values, element counting gives `null=2` and record counting gives `present=1`; deriving a null rate from them gives 200%. Empty arrays and mixed present/missing children need separate denominators. Both readers also return `Decimal` numbers, and nullable Arrow timestamps remain objects with null `.iso`/`.value` children (`infrastructure/readers/parquet.py`, `_wrap_timestamp`), rather than becoming top-level JSON nulls.

   **Fix:** define record coverage separately from observed-value counts, missing counts and null counts, with explicit denominators for each rate and hint. Specify JSON `number` handling for finite `Decimal`, boolean-versus-integer distinction, wrapper-kind versus JSON-object classification, and logical wrapper nulls. Preserve exact numeric values in the report and its text. Test arrays with mixed/missing/null elements, empty arrays, large integers, fractional decimals and null timestamp wrappers in the profiler tests and API serialization tests.

8. **P2 — The application port drops requested mapping identity and leaves the target contract ambiguous.** `ProposeMapping` accepts `source` and `name` (plan lines 64–65), but `AssistantContext` contains neither (lines 53–56), and `propose` takes only that context. The TraceLab fake consequently has no specified way to honor a request for a different name/source instead of returning the bundled document's identity. `target_schema` also needs to distinguish the executable DSL document schema from the canonical target entities and field requirements. The application-owned proposal and provider-neutral port are otherwise the correct direction under ADR-005.

   **Fix:** put the requested mapping identity and the complete, versioned mapping/target contract in application-owned DTOs, or explicitly make the application stamp and validate identity after each response. Document the policy for revise, where current document identity must remain coherent. Ensure both fake and future compatible adapters receive the same contract. Add tests that request non-default source/name, reject incompatible input formats, and verify provider/model/prompt metadata stays outside executable mapping semantics. Implement through `application/ports.py` and `application/dto.py`, without vendor types.

9. **P2 — “One repair” is not yet an implementable failure contract.** Plan lines 51–61 define only successful proposal returns; lines 71–73 require sending validation issues for repair, but neither the context nor the port specifies that input. No result/error shape distinguishes refusal, truncation, timeout, malformed response and an invalid mapping document. Those are explicitly required adapter responsibilities in ADR-005 lines 53–59. Without a shared policy, #14 can add its own repair loop beneath the application's loop, or a failed second response can become a 500 instead of final diagnostics. `parse_mapping(...).is_executable` establishes contract validity, not successful execution against source records.

   **Fix:** specify an application-owned failure model and an explicit repair request carrying the previous candidate and structured validation issues, whether implemented through `revise` or another port operation. Assign one owner for a maximum of two generation calls per user operation; revalidate the second result, return its diagnostics, and never fall back to treating refused/truncated text as a mapping. Bound diagnostic/raw-text sizes and sanitize returned diagnostics rather than returning SDK exceptions or authentication details. Document HTTP statuses and successful-but-invalid draft responses in `docs/api/v0.1.md`, preserving its error envelope. Use scripted fakes to test valid-first, invalid→valid, invalid→invalid, refusal, truncation, malformed output, timeout and repair failure, including exact call counts for propose and revise. Preserve the later `PreviewImport` and full-run stages; test a parse-valid proposal whose source identity path is missing, so parsing success cannot be mistaken for preview success.

10. **P2 — The planned helper reuse crosses enforced architecture boundaries.** Plan lines 62–75 place `dumps_exact` serialization and reuse of the bundled save path in application use cases. The existing helpers live in `infrastructure/jsonx.py:18` and `infrastructure/mappings/bundled.py:28`; there is no existing `SaveMappingRevision` application use case. Importing either implementation into application code violates the layer contract in `backend/pyproject.toml:63–71`. Recognizing `_arrow` dictionaries in a pure profiler is fine; importing the Parquet reader or pyarrow into that domain module is not.

   **Fix:** explicitly plan the dependency inversion: expose preparation/serialization through an application-owned port, or relocate a shared stdlib codec to an inward layer that its callers may import. Extract revision-saving orchestration into an application service using `MappingRepository`, `UnitOfWorkFactory`, `Clock` and IDs; make the infrastructure bundled loader call that service, not vice versa. Keep Arrow conversion in the reader and profile only its decoded values. Add import-linter, Ruff and mypy to the issue's completion checks, alongside tests; do not weaken `backend/pyproject.toml` to accommodate the implementation.

11. **P2 — The persistence promises contradict both the cache design and current storage.** Plan lines 73–82 promise no persistence while caching `uploads.profile`; lines 122–125 similarly demand no database writes without identifying which use cases that covers. `Upload` has no profile column (`infrastructure/db/models.py:76`), `UploadInfo` has no profile field (`application/dto.py:45`), and `UploadRepository` only has `add/get` (`application/ports.py:59`). The assertion that unredacted values exist only in the raw file is already false: `SqlAlchemyUploads.add` persists raw preview payloads at `infrastructure/db/repositories.py:78–80`. The new public save endpoint is also described only by analogy with a bundled loader that requires executable documents and stamps `created_by="bundled"`; that does not define the policy for editable assistant drafts.

   **Fix:** state the allowed writes separately: `ProfileFile` may update a sanitized cache; propose/revise may not save mappings, analysis conversations or canonical records; only explicit save creates a mapping revision. Plan the migration, repository/DTO methods, cache version/invalidation and restart behavior. Describe existing raw preview storage accurately without broadening this issue into trace-storage removal. Specify save validation, invalid-draft policy, provenance, content-hash idempotence and immutable revision behavior, including preservation of historical import bindings; do not label user saves as bundled. Add migration/upgrade and cache-restart tests, table-specific no-write assertions for propose/revise, and API tests for invalid saves, idempotent saves and edited revisions. Exercise all five newly listed routes, rather than the plan's “four endpoints,” through `docs/api/v0.1.md` contracts.

12. **P2 — The SWE-chat fake teaches a timestamp error and conflates two row shapes.** Plan lines 88–93 invent a `created_at` epoch-unit ambiguity and an edit to treat it as seconds. In the inspected selection, session `created_at` is an Arrow timestamp wrapper carrying `unit: "ns"`, `tz: "UTC"`, `.iso` and `.value`; conversations have `timestamp` wrappers with `unit: "us"`, and no `created_at` column. There is no seconds-versus-milliseconds ambiguity to resolve for these typed fields. A fake accepting the proposed edit can satisfy a revise test while producing an invalid or wrongly scaled mapping. The two source tables also cannot be recognized as a single interchangeable “SWE-chat-shaped profile.” Deferring complete source-mapping correctness to #16 does not justify inaccurate fixtures for the foundational port.

   **Fix:** define distinct session and conversation fake cases using production-reader output and the actual path sets. Prefer `.iso` with ISO-8601 parsing for these timestamp fields; reserve the epoch-unit correction scenario for a synthetic scalar timestamp whose unit really is ambiguous. Keep unresolved conversation/accounting semantics visibly unresolved. Add sanitized synthetic Parquet cases to CI so it needs neither gated downloads nor credentials, and record local checks against a reproducible whole-session excerpt. Resolve the excerpt script's schema-losing Python conversion separately in `scripts/sample_swe_chat.py:153` and `:82`, or explicitly track it as a prerequisite; do not claim the script or full SWE workflow was verified by this review's substitute selection.
