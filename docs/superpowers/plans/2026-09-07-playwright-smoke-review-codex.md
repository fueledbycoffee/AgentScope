1. **P1 — Waiting on e2e does not make its failure block merging.** `P:52` specifies only the dependency. `.github/workflows/ci.yml:75-82` explicitly tests only backend and web results; adding `needs: e2e` alone still produces success after an e2e failure.
   Require `needs: [backend, web, e2e]`, retain `if: always()` and the existing `ci-required` name, and explicitly require `needs.e2e.result == success`, including failure on skipped/cancelled results. Keep branch protection on this single aggregate check; verify the failure path.

2. **P1 — The new spec will enter the existing Vitest suite.** `P:11,20` puts a conventional spec under `web/e2e`, but `web/vite.config.ts:14-17` leaves default test discovery unrestricted and `web/package.json:12` runs `vitest run`. The installed Vitest default includes `**/*.{test,spec}.?(c|m)[jt]s?(x)`, so it will load Playwright tests under jsdom and fail.
   Explicitly separate discovery: Playwright `testDir: './e2e'`, Vitest restricted to unit tests or excluding e2e while preserving defaults. Also include the new config/spec in a TypeScript check: today's includes cover only `src` and `vite.config.ts` (`web/tsconfig.app.json:25`; `web/tsconfig.node.json:22`).

3. **P2 — Server readiness and working directories are underspecified.** `P:11-17` needs explicit config-relative backend/fixture paths, `use.baseURL`, host, readiness URL, startup timeout and a build-before-start contract for both scripts. The SPA mount is decided when the app is created (`backend/src/agentscope_app/interfaces/api/main.py:62,111-117`); building afterward cannot add it. Vite's development proxy targets port 8000, not 8765 (`web/vite.config.ts:8-12`).
   Start from an absolute backend cwd with `--host 127.0.0.1`, wait on `/api/health` after lifespan migrations/mapping loading, and verify a built deep link and its assets separately (`main.py:73-81`; `backend/src/agentscope_app/interfaces/api/container.py:53-63`). Disable server reuse for this data-mutating suite, including locally, so an unrelated database cannot be imported into. See [webServer readiness/cwd behavior](https://playwright.dev/docs/test-webserver).

4. **P2 — Sequential tests do not define safe shared-state lifetime or retries.** `P:14-20,30` leaves test 2 dependent on test 1 without specifying serial failure behavior; a new test also gets a fresh page.    Allocate one unique temp root before server startup, pass explicit absolute `sqlite:////…` and raw-directory values, retain both for the entire suite, and remove them only after server shutdown, including failure cleanup (`backend/src/agentscope_app/infrastructure/settings.py:12,19-20`; `backend/src/agentscope_app/infrastructure/files/raw_store.py:14-38`). Choose explicit serial mode, one worker, no parallelism, retries disabled unless the whole database/raw store/server is recreated; navigate each fresh page explicitly. Document how selected/UI reruns reseed dependencies. [Serial groups retry together](https://playwright.dev/docs/test-retries#serial-mode).
