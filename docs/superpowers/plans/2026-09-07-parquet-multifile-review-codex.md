1. **P1 — Migration 0003 changes the wrong part of record identity** (`plan:65–69`).
   `record_results.file_sha256` already exists; the primary key is only `(import_id, locator)` (`infrastructure/db/models.py:153–160`; `infrastructure/db/alembic/versions/0001_initial_schema.py:198–213`). Adding that column again fails migration; leaving the key unchanged makes two fresh JSONL files at `line:1`, or Parquet files at `row:0`, collide even though emission keys differ.
   Specify a SQLite table rebuild with primary key `(import_id, file_sha256, locator)`, retaining existing hashes/FKs; add and backfill only the missing reject hash. Test two fresh files of the same format on a migrated database—the planned mixed JSONL/Parquet case misses this collision.

2. **P1 — A mixed committed/duplicate batch conflicts with the existing commit protocol** (`plan:75–89`).
   `add_report(running)` already inserts and flushes every `import_files` row (`infrastructure/db/repositories.py:176–216`); `update_report(committed)` sets every row's `committed=True` (`:218–239`). A previously committed duplicate in the new batch then violates `uq_import_files_committed_source` (`infrastructure/db/models.py:130–140`), aborting the valid new file with 409. Inserting the per-file rows again after `traces.store` is also incorrect.
   Define one insertion/finalization protocol: flush the running import parent, insert file rows once, finalize only newly processed files as committed, leave duplicate audit rows noncommitted, and filter both committed lookups by file participation (`repositories.py:154–174`). Preserve the partial unique index as the race guard even for empty/session-only/all-rejected files, which need not have colliding model/tool occurrences.
   Inject failure after `traces.store`, after report finalization and during `add_results`, using real SQLite; assert rollback of entities, reducer updates and file claims, followed by one failed audit. Existing ordering and exception handling are `application/use_cases/imports.py:233–261`; a read failure in file two before persistence does not test transaction rollback.

3. **P1 — Different upload IDs can carry identical bytes inside one batch** (`plan:61,73–83`).
   Uploads receive fresh IDs independently of their content hash (`application/use_cases/uploads.py:63–74`). Two uploads of unseen bytes both pass the database pre-check before either is committed. Same mapping: duplicate emissions collide or duplicate session contributions; different mappings: changed rule IDs can evade occurrence collisions and inflate the reducer before the file uniqueness check aborts.
   Validate/group by `(source, sha256)` before mapping. Define deterministic treatment for identical mappings and reject ambiguous two-mapping bindings before writes; do not implicitly reprocess the same bytes under another revision (ADR-002, `docs/adr/ADR-002-identities.md:37–44`). Test both cases, replay with a changed mapping, and the same hash previously committed only under another source (which must remain importable here). `already_imported` is deliberately source-agnostic (`uploads.py:63`) and cannot decide commit duplication.

4. **P1 — Row batches and compressed upload size do not bound memory or the batch workload** (`plan:18–19,46–48,61,80–83`).
   A sub-25-MiB dictionary/compressed Parquet containing 100,000 repeated 100-KiB strings can expand to roughly 9.5 GiB of logical string content; even 1,000 decoded wide rows can be large. Arrow's batch size limits rows, not bytes. [ParquetFile.iter_batches](https://arrow.apache.org/docs/python/generated/pyarrow.parquet.ParquetFile.html#pyarrow.parquet.ParquetFile.iter_batches).
   Upload counts by decoding the entire file (`application/use_cases/uploads.py:49–61`); commit retains every payload, outcome, reject and emission (`application/use_cases/imports.py:208–232`), followed by repository row lists (`infrastructure/db/repositories.py:390–395,469–476`). Streaming the reader alone cannot fix this. Specify decoded-byte/row-width/nesting/expansion budgets before Python materialization, bounded accumulation or staging, and a resource-limit response. JSONL already has decompression and line limits (`infrastructure/readers/jsonl.py:23–24,60–64,82–95`).
   Twenty individually valid files also allow 2,000,000 records: enforce the aggregate 100,000-record batch limit required by `docs/adr/ADR-004-mapping-dsl-v1.md:58–63` and `docs/api/v0.1.md:140–142`, explicitly defining duplicate participation. Add highly compressed wide-row and aggregate-limit tests; no RSS measurement was performed here.

5. **P1 — Timestamp precision and naive-zone diagnostics are promised but absent** (`plan:24,34,55`).
   The pinned Arrow implementation raises for sub-microsecond ns timestamps/durations without pandas; converting the whole batch to Python before handling typed scalars can therefore fail valid input. Use integer scalar values plus schema units before conversion, including nested temporals. [Arrow scalar implementation, lines 597–622, 754–774](https://github.com/apache/arrow/blob/apache-arrow-21.0.0/python/pyarrow/scalar.pxi#L597).
   Independently, the actual domain probe converts `2026-09-07T12:00:00.123456789Z` to `.123456+00:00`; `parse_timestamp` assigns UTC to naive strings without any warning (`domain/units.py:102–116`). Canonical timestamps are Python datetime/SQLAlchemy DateTime (`domain/schema.py:56–57,67–68`; `infrastructure/db/models.py:40–54`). Full-precision raw text does not prevent canonical truncation or changed interval/bounds comparisons.
   Define supported range, an explicit diagnostic/rejection policy for unrepresentable precision and naive timestamps, and preserve original timezone/unit metadata where normalization discards it (ADR-003, `docs/adr/ADR-003-nulls-and-units.md:37–48`). Test 1 ns, negative epochs, every unit, non-UTC/DST offsets, out-of-Python-range dates and naive values through mapping and persistence, not just JSON round-trip.

6. **P1 — Nonfinite-to-null bypasses invalid-value policies and has no warning channel** (`plan:29`).
   `RawRecord` has only locator/payload/error (`application/dto.py:26–32`); preview and commit count only interpreter warnings (`application/use_cases/imports.py:135–136,220–221`). Nothing carries the promised reader warning. Replacing NaN with `None` also routes a supplied invalid measurement through `on_missing` (potentially a default zero), instead of `on_invalid` (`domain/mapping/interpreter.py:331–354,376–385`).
   Preserve the distinction between explicit null, NaN and signed infinities with located reader diagnostics/raw evidence, and define how mapping sees invalid input; a count-only warning is insufficient. This is required by ADR-003 (`docs/adr/ADR-003-nulls-and-units.md:22–40`). Test nonfinite nested fields with both invalid policies and missing defaults, plus persistence/API warning delivery; `dumps_exact` itself rejects nonfinite numbers (`infrastructure/jsonx.py:34–39`).

7. **P2 — The proposed temporal wrappers cannot be used by DSL v1** (`plan:33–36,43–45`).
   `convert_duration` accepts numeric scalars, not dictionaries (`domain/units.py:50–64`); the interpreter takes literal `unit_from/unit_to`, not a source unit path (`domain/mapping/interpreter.py:376–379`). `$.latency.$duration` fails the key grammar (`domain/mapping/paths.py:14–16,71–75`), and quoted-key indexing is unsupported. `$bytes` has the same accessibility problem.
   Choose path-accessible wrapper keys and document an executable mapping using a declared static unit, with mismatch validation; otherwise explicitly revise the DSL contract rather than adding an undeclared transform/dynamic unit operation (ADR-004, `docs/adr/ADR-004-mapping-dsl-v1.md:39–63,105–108`). Keep time-of-day distinct from elapsed duration. Test an actual wrapper mapping, not only wrapper serialization.

8. **P2 — Historical migration and failed-file report semantics remain undefined** (`plan:65–71,88–91,131–132`).
   Existing failed attempts persist file rows (`application/use_cases/imports.py:259–274`), but the new per-file status admits only committed/duplicate; neither describes an aborted file. Per-file outcome counts are promised without a storage/derivation plan, especially for skipped duplicates and failures. Specify nullable/running/failed states and stable GET/list reconstruction, not just the immediate POST response (`infrastructure/db/repositories.py:291–307`).
   Backfill reject hashes by the old single-file import relationship, mapping references from imports, and historical counts/statuses from audit data. Databases upgraded from populated 0001 to 0002 can have `source=''` and `committed=0`: 0002 adds defaults but never backfills (`infrastructure/db/alembic/versions/0002_import_files_source_and_committed_.py:23–37`). Account for these rows when preserving/rebuilding the unique index; do not infer historical status solely from that boolean. Test populated 0001→0002→0003 and populated 0002→0003 with committed, duplicate and failed attempts, FKs enabled, retained raw payloads, and readable reports/rejects.

9. **P2 — Per-emission mapping provenance needs an explicit repository input** (`plan:80–95`).

Test two mappings emitting into one session and inspect every contribution's file, mapping, rule and parent link.

Preserve per-pair preview invalidation on upload/mapping changes (`:42,63–65`) and show bindings at final confirmation (ADR-004, `docs/adr/ADR-004-mapping-dsl-v1.md:33–34,90–93`).

Keep a batch-of-one adapter or explicitly version/migrate the contract; a same-PR client rebuild does not update an already open tab. Also preserve unknown-ID 404 behavior (`application/use_cases/imports.py:47–64`; `docs/api/v0.1.md:140`) instead of folding it into invalid_input. Test namespace selection, stale previews, client request serialization and historical report rendering.

11. **P2 — JSON round-trip cannot prove losslessness or total reader behavior** (`plan:21–24,120–137,146–148`).
    A dict keyed by column name cannot preserve duplicate column names; duplicate nested struct names can also make Arrow conversion fail. Wrappers can collide with real source structs of the same shape. Require schema validation and retained type metadata or an explicit unsupported-schema policy before conversion. [Arrow struct conversion, lines 1008–1016](https://github.com/apache/arrow/blob/apache-arrow-21.0.0/python/pyarrow/scalar.pxi#L1008).
    Cover unlisted logical/extension types: ParquetFile can decode UUID/JSON as Arrow extensions by default; decide supported conversion or a located rejection, rather than relying on generic serialization. [ParquetFile options](https://arrow.apache.org/docs/python/generated/pyarrow.parquet.ParquetFile.html). `infrastructure/jsonx.py:25–69` only knows a closed Python type set.
    Restrict “never raises” to supported, within-budget files: the same plan requires corrupt/over-limit inputs to raise. Assert Arrow-value→expected-payload fidelity as well as JSON round-trip (a converter returning `{}` for every row passes the latter). Exercise real Parquet write/read schemas, since on-disk round-trip can change Arrow types; test absent Arrow metadata, dictionary decoding, duplicate map keys and nested null combinations explicitly.

12. **P2 — Locator stability is specified correctly but the tests do not protect it** (`plan:18–21,120–124`).
    Use one absolute row counter across every yielded batch and row group, not group-local indices or `batch_number * 1000` (batches may be shorter). Add uneven multiple row groups crossing 1,000-row boundaries and read the same bytes with different batch sizes; assert identical locators, payload lookup, nested emission keys and replay counts through upload/preview/commit.

An empty/new-file batch and a wholly duplicate batch should retain audit reports while adding no entities; “inserts nothing” must not mean losing the attempt history (`application/use_cases/imports.py:203–206`).
